stoqr Android — Regressions-Report & Test-Leitfaden

Deine gemeldeten Beobachtungen (Test der Version v0.2.6), die jeweilige Ursache, der durchgefuehrte Fix und wie/wo zu testen ist. Stand: Phase 1 (Datenpfad) UND Phase 2 (UI/Design-System) abgeschlossen.

BEHOBEN = im aktuellen Release enthalten (Phase 1 Datenschicht + Phase 2 UI).  ·  Detaillierte technische Testfaelle: docs/test-manifest.html Bloecke G59 (Schreiboperationen), G60 (UI/Design-System), G56–G58.

Generell

BEHOBEN App-Logo & Drawer fehlen

Ursache
Die Schrift (Sora/Inter) wird per Remote-@import von Google Fonts geladen — offline im WebView tot, daher degradiert der „stoqr"-Schriftzug. Der Drawer selbst ist korrekt verdrahtet.
Fix
Schriften lokal gebuendelt (@font-face + WOFF2 in static/fonts/) statt Remote-@import. G60-1.
Test
Schriftzug „stoqr" in der gewohnten Schrift; Hamburger-Menue oeffnet den Drawer.

BEHOBEN Einheiten in Select-Feldern doppelt

Ursache
Keine Eindeutigkeit auf units.symbol; Seed-System-Einheiten und importierte/zugefuegte Haushalts-Einheiten mit gleichem Symbol koexistieren; getUnits merged ohne Dedupe.
Fix
Dedupe nach Symbol in getUnits (System bevorzugt). G60-3.
Test
In jedem Einheiten-Dropdown jedes Symbol nur EINMAL.

BEHOBEN Pruefungs-Pill „Pruefung nicht moeglich" / falsche Version

Ursache
Offline-Stub liefert reason:'offline' (nicht als benigne Meldung gemappt) und eine hart codierte Version 0.1.0.
Fix
offline-Meldung freundlich gemappt; echte Build-Version (aus package.json) angezeigt. G60-4.
Test
Pill zeigt aktuelle Version + neutralen Offline-Hinweis statt Fehler.

Einstellungen

BEHOBEN Scroll-Position bei Breadcrumb-Zurueck verloren

Ursache
Unterseiten sind eigene Routes; Breadcrumb ist ein normaler Link -> SvelteKit scrollt nach oben; keine Scroll-Wiederherstellung.
Fix
Breadcrumb nutzt history.back() -> SvelteKit-Scroll-Restore. G60-5.
Test
Zurueck ueber Breadcrumb behaelt die Scroll-Position.

BEHOBEN Artikel anlegen/bearbeiten scheitert still

Ursache

Fix
Schema-Provider (App nutzt SQLite-Tabellen) + id-Default. G59-1.
Test
Neuen Artikel anlegen; bestehenden bearbeiten (inkl. Pfand). Speichern ohne Fehler, Werte sichtbar.

BEHOBEN Katalog-Sicherung: „Offline: nicht verfuegbar"

Ursache
Erwartet: Katalog-Sync ist ein reiner Online-Netzabruf; offline (App) bewusst degradiert. Kein Fehler, sondern korrektes Verhalten.
Fix
Keiner noetig (die Meldung ist gewollt; der Preis-Abruf-Schalter ist eine getrennte, on-device gespeicherte Praeferenz).
Test
Meldung bleibt — das ist beabsichtigt, solange die App offline arbeitet.

BEHOBEN „Sync in Vorbereitung"-Karte sieht wie Textwueste aus

Ursache
Cross-Component Scope-Leakage: die Komponente nutzt Parent-CSS-Klassen, die Svelte-Scoping nicht durchreicht. Speichern warf zusaetzlich „Not found".
Fix
„Not found" behoben (routeApp settings/sync-Zweig, G59-4). Darstellung ueber globale Control-Primitiven in app.css (Scope-Leakage behoben). G60-2.
Test
Sync-Karte korrekt gestylt (nicht mehr wie Textwueste); Speichern ohne „Not found".

BEHOBEN Gefahrenzone-Modals: Buttons ausserhalb/abgeschnitten

Ursache
Modal-Footer nutzt Parent-Klassen (Scope-Leakage) + fehlendes max-height/overflow.
Fix
Funktion behoben (Werksreset A/B/C laeuft on-device, G59-4/5); Modal-Footer-Buttons ueber globale Primitiven gestylt (Scope-Leakage behoben). G60-2.
Test
Werksreset A/B/C mit korrekter Phrase fuehrt aus (Stufe C stellt Kategorien/Naehrwerte wieder her); Modal-Buttons korrekt im Rahmen.

So testest Du die Phase-1-Fixes (jetzt)

Sobald das naechste App-Release installiert ist, die mit BEHOBEN markierten Punkte durchgehen — alle Schreib-Aktionen sollten ohne SQL-Fehler speichern. Empfohlene Reihenfolge:

  1. Einstellungen → Danger-Zone → Werksreset Stufe C (frischer, konsistenter Stand).
  2. Raum + Lagerort + Fach anlegen.
  3. Kategorie (Haupt + Unter) + Kategorie-Zuordnungsregel anlegen.
  4. Artikel anlegen, Pfand setzen, Bestand korrigieren, Soll-/Mindestbestand, Markt-Zuordnung, Preis erfassen.
  5. MHD-Ampel + MHD-Toleranz je Kategorie speichern; Preis-Abruf-Schalter; Sync-Karte speichern.
  6. „Alles loeschen" auf einem Testartikel.

Technische Detail-Testfaelle mit Schritten & Erwartung: docs/test-manifest.html → Block G59 (und G56–G58 fuer die vorherigen Fixes).
